# نشر Dahab ERP على Hostinger

هذه الخطوات تخص نسخة Laravel كاملة على استضافة تدعم PHP 8.4 وSSH وCron وقاعدة MySQL. تحقق من توفر هذه الخدمات في خطتك قبل النقل. اجعل جذر الموقع يشير إلى مجلد `public` داخل المشروع، ولا تنسخ `.env` أو `storage` إلى مجلد عام.

## قبل النقل

- أنشئ قاعدة MySQL ومستخدمًا ببيانات خاصة بهذا الموقع، واضبط النسخ الاحتياطي للقاعدة والملفات المرفوعة.
- احفظ نسخة مستقلة من قاعدة البيانات وملفات `storage/app/public` ومفتاح `APP_KEY` عند الترقية. لا تغيّر المفتاح لموقع قائم؛ فهو يستخدم للبيانات المشفرة ومنها إعدادات التكامل.
- جهز إعدادات SMTP صحيحة وصندوق بريد لاختبار التقارير المجدولة. إعداد `MAIL_MAILER=log` لا يرسل رسائل.
- استخدم HTTPS خصوصًا لبوابة الموظف والكاميرا. إن استُخدم CompreFace فاضبط عنوانًا يمكن للخادم الوصول إليه ومفتاح API في إعدادات الحضور؛ خدمة `127.0.0.1` على جهازك لا تنتقل تلقائيًا إلى الاستضافة.

## على الخادم

بعد رفع الكود، داخل مجلد المشروع:

```bash
composer install --no-dev --prefer-dist --optimize-autoloader
npm ci
npm run build
```

أنشئ `.env` من `.env.example` **لموقع جديد فقط**، ثم اضبط `APP_ENV=production` و`APP_DEBUG=false` و`APP_URL=https://your-domain.example` وبيانات MySQL والبريد. تأكد أن `APP_KEY` محفوظ وسري؛ استخدم `php artisan key:generate` في تثبيت جديد فقط. لا تستخدم حسابات أو بيانات العرض التجريبي على موقع عميل.

```bash
php artisan migrate --force
php artisan storage:link
php artisan optimize
```

يحتاج خادم الويب إلى قراءة المشروع والكتابة في `storage` و`bootstrap/cache`. تحقق من وصول المتصفح إلى الصور والشعار عبر `/storage/...` وأن رابط التخزين الرمزي يشير إلى `storage/app/public`. عند تعذر الروابط الرمزية في الخطة، يلزم حل استضافة مناسب قبل اعتبار رفع الصور جاهزًا.

## المهام الدورية والبريد

أنشئ مهمة Cron واحدة كل دقيقة (استبدل المسار ومسار PHP بمسارات استضافتك):

```cron
* * * * * cd /absolute/path/to/project && /absolute/path/to/php artisan schedule:run >> /dev/null 2>&1
```

راجع `php artisan schedule:list`، ثم أرسل تقريرًا تجريبيًا إلى بريد تتحكم فيه من شاشة التقارير المجدولة وتحقق من وصوله والمرفق. نجاح `schedule:run` وحده لا يثبت وصول SMTP. إذا غُيّر `QUEUE_CONNECTION` من `sync` إلى مشغل طوابير، شغّل عامل `queue:work` دائمًا بإشراف مناسب.

## فحص ما بعد النشر

- افتح تسجيل الدخول والإعدادات والواجهة والكاشير من اسم النطاق الفعلي، وافحص عرض الشعار وصور المنتجات.
- جرب مستخدمًا بصلاحيات محدودة وتأكد أن صفحات HR والمالية لا تظهر له بغير صلاحية.
- أنشئ عملية اختبار آمنة لطباعة فاتورة والتحقق من وسيلة الدفع؛ لا تستخدم بيانات إنتاج حقيقية للتجربة.
- راجع `storage/logs` وأخطاء الخادم بعد اختبار البريد والتقارير والجدولة.
- قبل كل ترقية لاحقة خذ نسخة احتياطية، وارفع الكود، ثم نفذ `composer install --no-dev --prefer-dist --optimize-autoloader` و`npm ci && npm run build` و`php artisan migrate --force` و`php artisan optimize`، مع إبقاء `.env` وملفات `storage` الخاصة بالموقع.
